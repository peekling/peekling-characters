# অফিসিয়াল Peekling ক্যারেক্টার প্যাক

Peekling এর ব্যক্তিত্ব প্রদানকারী ছোট চরিত্রগুলির সাথে দেখা করুন।

Peekling প্রকল্প দ্বারা তৈরি এবং রক্ষণাবেক্ষণ করা চরিত্র প্যাকগুলির জন্য এটি অফিসিয়াল হোম। প্রতিটি প্যাক বর্ণনা করে যে কীভাবে একটি অক্ষর দেখায়, নড়াচড়া করে, প্রতিক্রিয়া জানায় এবং একটি সামঞ্জস্যপূর্ণ Peekling রানটাইমের সাথে নিজেকে পরিচয় করিয়ে দেয়। প্যাকগুলি ওপেন সোর্স, শুধুমাত্র ডেটা, এবং স্বাধীনভাবে সংস্করণ।

[Peekling সংগঠন](https://github.com/peekling) দেখুন, অথবা [প্যাক অথরিং গাইড](../PACK-AUTHORING.md) পড়ুন কিভাবে একটি অক্ষরকে একত্রিত করা হয়।

##  একটি অক্ষর প্যাক কি?

একটি অক্ষর প্যাক ডেটা এবং চিত্রের একটি ছোট বান্ডিল। এটিতে এক্সিকিউটেবল চরিত্রের আচরণ নেই।

প্রতিটি অফিসিয়াল প্যাক অন্তর্ভুক্ত:

- a `character.json` চরিত্রের পরিচয়, অবস্থা, আন্দোলন, সংস্করণ এবং লাইসেন্সের সাথে প্রকাশ করে
- বিভিন্ন ডিসপ্লে ঘনত্বের জন্য 1x, 2x এবং 4x PNG অ্যাটলাস
- a `thumbnail.png` পূর্বরূপ
- এর নিজস্ব `README.md`, `LICENSE`, এবং `NOTICE`

ম্যানিফেস্ট প্রতিটি অ্যাটলাসের জন্য নিরাপদ আপেক্ষিক চিত্র পাথ এবং SHA-256 হ্যাশ রেকর্ড করে। ডেভেলপমেন্ট স্ক্রিপ্ট, টেস্ট, সোর্স আর্ট এবং জেনারেট করা QA রিপোর্ট এই রিপোজিটরিতে এবং প্রকাশিত প্যাকেজ সীমানার বাইরে থাকে।

## Peekling অক্ষর

এই টেবিলটি বর্তমান প্যাকেজ মেটাডেটা এবং লাইভ npm রেজিস্ট্রি থেকে তৈরি করা হয়েছে। প্রকাশিত সারিগুলি তাদের যাচাইকৃত npm সংস্করণে লিঙ্ক করে৷ যে প্যাকগুলি এখনও শুধুমাত্র-উৎস আছে সেগুলি একটি স্পষ্ট `(অপ্রকাশিত)` লেবেল এবং কোন npm লিঙ্ক সহ দৃশ্যমান থাকে৷

প্যাকেজ মেটাডেটা পরিবর্তন করার পরে বা প্রকাশের পরে `npm run roster` চালান৷ `npm run roster:check` npm প্রকাশনার অবস্থা যাচাই করে এবং প্রতিটি অপ্রকাশিত প্যাকেজ পরিষ্কারভাবে লেবেলযুক্ত রাখে।

##  একটি প্যাক ব্যবহার করা

যখন একটি অক্ষর টেবিলে উপস্থিত হয়, যাচাইকৃত ইনস্টলযোগ্য সংস্করণের জন্য npm এর প্যাকেজ লিঙ্কটি অনুসরণ করুন৷ এর উত্স ডিরেক্টরিটি বৈধতা আদেশ এবং লাইসেন্স রেকর্ডগুলি নথিভুক্ত করে, যখন `character.json` চরিত্রের অবস্থা, আন্দোলন, শিল্পকর্ম এবং ক্ষমতাগুলির জন্য সত্যের উত্স থাকে৷

শুধুমাত্র একটি npm লিঙ্ক সহ সারিগুলিকে ইনস্টলযোগ্য হিসাবে যাচাই করা হয়েছে৷ একটি `(অপ্রকাশিত)` সারি ভবিষ্যতের ফলো-আপের জন্য সংগ্রহস্থলের উত্সকে নির্দেশ করে এবং এটি একটি প্রাপ্যতা দাবি নয়। উত্স ডিরেক্টরিতে npm এর থেকেও নতুন কাজ থাকতে পারে৷ Peekling রানটাইম এই ক্যারেক্টার প্যাকগুলি থেকে আলাদা এবং ম্যানিফেস্ট লোড করার জন্য এবং এর রেফারেন্সড অ্যাটলাস রেন্ডার করার জন্য দায়ী৷

রিপোজিটরি রুটে ওয়ার্কস্পেস ব্যক্তিগত এবং প্রকাশ করা যাবে না। শুধুমাত্র পৃথক `packages/pack-*` ওয়ার্কস্পেস রিলিজ সীমানা।

##  একটি চরিত্র তৈরি করুন

একটি নতুন ছোট বন্ধু জন্য একটি ধারণা আছে? একটি প্যাকের সৃজনশীল মূলের তিনটি অংশ রয়েছে:

- `character.json` চরিত্র, এর অ্যানিমেশন অবস্থা, গতিবিধি, সংস্করণ, লাইসেন্স এবং অ্যাটলাস ফাইল বর্ণনা করে।
- `atlas-1x.png` সাধারণ প্যাক চুক্তির ন্যূনতম আর্টওয়ার্ক অ্যাটলাস। একটি অফিসিয়াল প্যাকে অবশ্যই মিল থাকা `atlas-2x.png` এবং `atlas-4x.png` ভেরিয়েন্ট অন্তর্ভুক্ত করতে হবে।
- `thumbnail.png` হল গ্যালারী এবং প্যাকেজ তালিকায় দেখানো ছোট প্রিভিউ।

একটি অফিসিয়াল প্রকাশযোগ্য প্যাকেরও প্রয়োজন `package.json`, `README.md`, `LICENSE`, `NOTICE`, এবং প্রতিটি অ্যাটলাস এর ম্যানিফেস্ট দ্বারা নামকরণ করা৷ [প্যাক অথরিং গাইড](../PACK-AUTHORING.md) দিয়ে শুরু করুন এবং একটি সম্পূর্ণ উৎস উদাহরণ হিসেবে [Peek এর প্যাকেজ](../packages/pack-peek) ব্যবহার করুন।

বর্ধিত তৈরির সরঞ্জামগুলি প্রকাশিত হলে এখানে লিঙ্ক করা হবে৷ ততক্ষণ পর্যন্ত, অথরিং গাইড, প্যাকেজ ম্যানিফেস্ট এবং বর্তমান অফিসিয়াল প্যাকগুলি সত্যের উৎস।

##  অবদান

চিন্তাশীল সংশোধন এবং ফোকাসড উন্নতি স্বাগত জানাই. আপনি যদি একটি নতুন অফিসিয়াল চরিত্র বা একটি বড় পরিবর্তনের প্রস্তাব করতে চান, অনুগ্রহ করে প্রথমে [একটি সমস্যা খুলুন](https://github.com/peekling/peekling-characters/issues) করুন যাতে আমরা সুযোগ, শিল্পকর্মের উৎস এবং লাইসেন্সিং বিষয়ে একমত হতে পারি।

আপনার প্রয়োজন হবে Node.js 22 বা তার পরে। ওয়ার্কস্পেস তার প্যাকেজ ম্যানেজার হিসেবে npm 11.19.0 রেকর্ড করে।

1. একটি নতুন চরিত্রের জন্য একটি সমস্যা খুলুন যাতে আপনি অনেক কাজ করার আগে তার নাম, অফিসিয়াল সংগ্রহে স্থান, শিল্পকর্মের মালিকানা এবং লাইসেন্স নিয়ে আলোচনা করা যেতে পারে। একটি বিদ্যমান প্যাকের পরিবর্তনগুলি শুধুমাত্র তার কোড মালিক বা মনোনীত পর্যালোচক অনুমোদন করার পরেই গৃহীত হয়৷
2.  সংগ্রহস্থলটি কাঁটা এবং ক্লোন করুন, তারপর `npm install` দিয়ে ওয়ার্কস্পেস নির্ভরতাগুলি ইনস্টল করুন।
3.  একটি নতুন ছোট হাতের শনাক্তকারী নির্বাচন করুন যেমন `my-friend`। এটি একটি অক্ষর ডিরেক্টরি, ম্যানিফেস্ট নাম, বা npm প্যাকেজ নকল করা উচিত নয়৷ কাঠামোগত উদাহরণ হিসাবে [Peek এর সম্পূর্ণ উৎস প্যাকেজ](../packages/pack-peek) ব্যবহার করুন এবং `packages/pack-my-friend` তৈরি করুন।
4.  প্রকাশযোগ্য সীমানা তৈরি করুন:

   - `package.json` নাম `@peekling/pack-my-friend`, একটি শব্দার্থিক সংস্করণ, সর্বজনীন অ্যাক্সেস, লাইসেন্স, সংগ্রহস্থল ডিরেক্টরি, নির্মাণ এবং পরীক্ষা স্ক্রিপ্ট এবং সঠিক পাবলিক ফাইল ঘোষণা করে।
   - `character.json` ফর্ম্যাট 1 এবং একই নাম, সংস্করণ এবং লাইসেন্স ব্যবহার করে। এটিকে একটি শিরোনাম, লেখক, বিবরণ, 1x/2x/4x অ্যাটলাস রেকর্ড, বৈধ ফ্রেম এবং সময় সহ অ্যানিমেশন স্টেট, সমস্ত আটটি চলাচলের দিকনির্দেশ এবং একটি ইতিবাচক ডিফল্ট স্কেল দিন।
   - `thumbnail.png` একটি বৈধ 64x64 PNG। বর্তমান অফিসিয়াল গ্রিড 64-পিক্সেল লজিক্যাল সেল, 16টি কলাম এবং 3টি সারি ব্যবহার করে, তাই তিনটি অ্যাটলেস হল 1024x192, 2048x384 এবং 4096x768৷ তাদের ঘোষিত ঘনত্ব, কক্ষের আকার, মাত্রা এবং SHA-256 হ্যাশ অবশ্যই সম্মত হবে।
   -  `README.md`, `LICENSE`, `NOTICE`, একটি ফোকাসড পরীক্ষা, এবং ম্যানিফেস্ট দ্বারা উল্লেখ করা প্রতিটি অ্যাটলাস যোগ করুন। `files` তালিকার বাইরে উৎস শিল্প ও উন্নয়ন সহায়কদের রাখুন।
   - বর্তমান ম্যানুয়াল আর্ট পাইপলাইনের জন্য, অক্ষরটিকে `scripts/build-character-roster.mjs`-এ এর প্রয়োজনীয় মেটাডেটা এবং আন্দোলনের রেকর্ড যুক্ত করুন। বিদ্যমান প্যাকগুলির দ্বারা ব্যবহৃত একই সংগ্রহস্থল-শুধু উৎস ইনপুটগুলি সরবরাহ করুন যাতে `npm run build` হাতে-সম্পাদিত আউটপুট গ্রহণ না করে অ্যাটলেসগুলি পুনরুত্পাদন করতে পারে৷

5.  ফোকাসড প্যাকেজ পরীক্ষা চালান এবং তৈরি করুন। Peek এর জন্য, সমতুল্য কমান্ডগুলি হল:

   ```sh
   npm test -w @peekling/pack-peek
   npm run build -w @peekling/pack-peek
   ```

6. যদি প্যাকেজ মেটাডেটা পরিবর্তিত হয়, `npm run roster` দিয়ে এই টেবিলটি পুনরায় তৈরি করুন, তারপর `npm run check` দিয়ে সম্পূর্ণ সংগ্রহস্থলের গেটটি চালান।
7. চালান `npm run changeset` এবং প্রতিটি প্রভাবিত প্যাক অন্তর্ভুক্ত করুন। প্যাক ডিরেক্টরির অধীনে প্রতিটি ফাইল পরিবর্তনের জন্য আর্ট, JSON, মেটাডেটা, ডক্স, টেস্ট এবং সোর্স ফাইল সহ একটি সংস্করণের সিদ্ধান্ত প্রয়োজন। স্তরটি নিজেই চয়ন করুন:
   - সামঞ্জস্যপূর্ণ সংশোধন বা টিউনিংয়ের জন্য `patch`
   - `minor` অর্থপূর্ণ পিছনের-সামঞ্জস্যপূর্ণ সংযোজন বা যথেষ্ট সৃজনশীল আপডেটের জন্য
   - ব্রেকিং পরিবর্তন, প্রতিস্থাপন বা অপসারণের জন্য `major`

   অটোমেশন কখনই আপনার পরিবর্তনের আকার বা ধরন থেকে স্তর অনুমান করে না।

8. একটি পুল অনুরোধ খুলুন যা এর শিল্পের চরিত্র, উত্স এবং লাইসেন্স ব্যাখ্যা করে, কী পরিবর্তন হয়েছে এবং কেন নির্বাচিত সংস্করণ স্তরটি উপযুক্ত।

পর্যালোচনা করার আগে, পুল-অনুরোধ CI-এর প্রতিটি পরিবর্তিত প্যাকের জন্য একটি রিলিজ পরিকল্পনা প্রয়োজন। এটি তারপরে ম্যানিফেস্ট চুক্তি এবং রাষ্ট্রের সংজ্ঞা, শনাক্তকারীর স্বতন্ত্রতা, নতুন প্যাকের জন্য অব্যবহৃত npm নাম, নিরাপদ চিত্র পাথ এবং হ্যাশ, PNG অখণ্ডতা, থাম্বনেইল আকার, 1x/2x/4x অ্যাটলাস অস্তিত্ব এবং স্কেল জ্যামিতি, সীমাবদ্ধতা, পুনঃনির্মাণযোগ্য আকার, সীমাবদ্ধতা, পরীক্ষা করা হয়। প্রতিটি npm প্যাকেজে সঠিক ফাইল ড্রাই-রান। এই চেকগুলি দুর্ঘটনাজনিত দ্বন্দ্ব এবং প্যাকেজিং ভুলগুলি প্রতিরোধ করে. মানব পর্যালোচকরা এখনও সিদ্ধান্ত নেয় যে কোনও চরিত্র বা পরিবর্তন সরকারী সংগ্রহের অন্তর্গত কিনা।

একটি বৈধ পরিবর্তন `main` এ পৌঁছানোর পরে, Changesets পর্যালোচনার জন্য একটি পৃথক সংস্করণ পুল অনুরোধ প্রস্তুত করে৷ প্রথম npm প্রকাশনাটি একটি ইচ্ছাকৃত রক্ষণাবেক্ষণকারী কর্ম থেকে যায়। স্বয়ংক্রিয় OIDC প্রকাশনা শুধুমাত্র প্রাথমিক প্যাকেজ বিদ্যমান থাকার পরে সক্ষম করা যেতে পারে এবং প্রতিটি প্যাকেজ এই সংগ্রহস্থলের প্রকাশ কর্মপ্রবাহকে বিশ্বাস করে। বুটস্ট্র্যাপ সম্পূর্ণ না হওয়া পর্যন্ত, সংগ্রহস্থল উৎস একটি প্রতিশ্রুতি নয় যে npm থেকে একটি প্যাকেজ উপলব্ধ। সম্পূর্ণ রক্ষণাবেক্ষণকারী প্রবাহের জন্য [মুক্তির প্রস্তুতি](../RELEASING.md) দেখুন।

এই রিপোজিটরিটি অফিসিয়াল Peekling প্যাকগুলির জন্য কিউরেটেড হোম, কোনও বিশ্ব সম্প্রদায়ের ক্যাটালগ নয়। নির্মাতারা তাদের নিজস্ব প্যাকেজ বা বৈধ পাবলিক লাইসেন্স সহ স্ট্যাটিক-হোস্টিং সীমানা থেকে সামঞ্জস্যপূর্ণ তৃতীয় পক্ষের প্যাকগুলি প্রকাশ করতে পারেন।

## লাইসেন্সিং এবং অ্যাট্রিবিউশন

সংগ্রহস্থল টুলিং, পরীক্ষা, এবং ডকুমেন্টেশন [Apache-2.0](../LICENSE) এর অধীনে লাইসেন্সপ্রাপ্ত। সমস্ত 28টি বর্তমান অফিসিয়াল ক্যারেক্টার প্যাকগুলিও Apache-2.0 ঘোষণা করে এবং তাদের নিজস্ব `LICENSE` এবং `NOTICE` ফাইল বহন করে৷

পুনর্বন্টন অবশ্যই প্রতিটি প্যাকের জন্য প্রযোজ্য লাইসেন্স এবং বিজ্ঞপ্তির শর্তাবলী অনুসরণ করবে। Peekling নাম, লোগো, অফিসিয়াল মাসকট, এবং অন্যান্য স্বতন্ত্র ব্র্যান্ড পরিচয় টুলিং লাইসেন্স দ্বারা মঞ্জুর করা হয় না যদি না একটি নির্দিষ্ট সম্পদ লাইসেন্স অন্যথা বলে। সম্পূর্ণ রেকর্ডের জন্য [লাইসেন্সিং এবং অ্যাট্রিবিউশন](../LICENSING.md), [NOTICE](../NOTICE), এবং [AUTHORS](../AUTHORS) দেখুন।
